# 跑马灯修复复盘与经验固化（v2.0.4 · 2026-10-15）

## 一、技术根因（一句话）

**v2.0.2 调用官方 `Modifier.basicMarquee` 时位置参数错位：第 1 个位置传了 `0`，落到了 `iterations` 上。官方语义 `iterations = 0` = 禁用动画，于是 `runAnimation()` 首行 `if (iterations <= 0) return` 直接返回 → 文本永不滚动（"字不动"）。**

```kotlin
// 错误（v2.0.2 ~ v2.0.3 取证版）：位置传参
.basicMarquee(0, Immediately, Int.MAX_VALUE, 0, MarqueeSpacing(gapDp), 33.dp)
//        ↑ iterations=0 → 官方禁用动画！

// 正确（v2.0.4）：命名参数
.basicMarquee(
    iterations = Int.MAX_VALUE,   // 无限循环
    animationMode = MarqueeAnimationMode.Immediately,
    repeatDelayMillis = 0,        // 轮间无停顿（无缝衔接）
    initialDelayMillis = 0,       // 无首轮延迟
    spacing = MarqueeSpacing(gapDp), // 两份文本间距 ≈ 2 字符
    velocity = 33.dp
)
```

官方签名：`basicMarquee(iterations, animationMode, repeatDelayMillis, initialDelayMillis, spacing, velocity)`。
注释也同步错位（把 0 注释成 initialDelay、把 Int.MAX_VALUE 注释成 repeatCount）——**注释写的是期望语义，代码传的却是另一个位置**，进一步掩盖了问题。

## 二、完整问题链条（为什么改了这么多轮）

### 阶段 1：自研方案反复叠字（v1.6.4 → v2.0.1a）
- 自研方案 = TextMeasurer 无约束测量 + Row 双份拼接 + Animatable 手动循环。
- 深层根因：**测量宽度与真实渲染宽度不一致**（字体 fallback、密度舍入），动画周期与布局拼接依赖手工同步，任何偏差都表现为叠字/空屏/跳变。
- 错误做法：在**现象层打补丁**——dp/px 换算（v2.0.1a）、加大 gap（v2.0.1 投机式"gap ≥ 视口宽"）——每次只缓解症状，没质疑"自研方案"本身。
- 用户拆穿投机方案（v2.0.1 gap≥视口宽）后，v2.0.2 才切换官方 `basicMarquee`。

### 阶段 2：切官方后"字不动"（v2.0.2 → v2.0.3 取证版）
- v2.0.2 切官方时引入参数错位（iterations=0），真机反馈"字不动"。
- 排查走了大量弯路（详见第三节），最终靠**逐行读自己的调用代码**定位。

### 阶段 3：根治（v2.0.4）
- 命名参数 + textAlign 按分支恢复 + 测试重构（233 全绿）+ 真机验收通过。

## 四、经验固化（可复用规则/清单）

### R1 调用库 API 一律用命名参数
多参数 + 有默认值的 API（Compose Modifier 尤其多），**禁止位置传参**。命名参数让"参数语义"在调用处自文档化，错位从根上不可能发生。

### R2 核对参数语义时逐条对文档，特别注意"反直觉"语义
`iterations = 0` 禁用动画、`-1` 表示无限、`0` 表示无延迟……这类语义要逐条对照 KDoc，**注释必须与实际参数一致**（写注释时对照代码，不能按期望语义写）。

### R3 UI bug 排查顺序：先读调用代码 → 再查实现/环境
正确顺序：
1. **读自己的调用代码**（参数、上下文、包裹方式）——80% 的 bug 在这里
2. 对照官方文档/源码确认预期行为
3. 再排除环境因素（依赖版本、主题设置、系统设置）
4. 最后才是取证/真机验证

禁止先验"官方没问题""环境没问题"——**这是本次最大的时间黑洞**。

### R4 取证点要选"决定行为的量"
加 DBG 诊断时，打印**真正进入实现的输入**（如传给官方节点的参数、官方节点收到的 contentWidth/containerWidth），而不是外围旁证（我们自己另测的宽度）。本次若打印"传给 basicMarquee 的 6 个参数"，一轮就能定位。

### R5 明确验证环境边界
- Robolectric：**captureToImage 不可用**（WindowCapture 异常）、**waitForIdle 不感知动画帧**（对照实验证实）→ **UI 动画/像素验证只能真机**。
- 在开始动画类排查前，先确认验证通道可用，不把时间花在"证明测试方法可行"上。

### R6 UI 修复流程（用户已确立，本次为其完整案例）
**先复现 → 找根因（能解释为什么原值会出问题）→ 修复 → 按复现路径验证**。
禁止"调参数缓解症状"的投机交付；禁止"先做出来再看"；交付前先向用户列出改动范围。

### R7 沟通：区分"现象描述"与"需求定义"
用户描述的是**现象**（叠字、不动、空屏）还是**需求**（无缝、两字符间距、循环）要分开记录。复述口径时用用户原话，不自行翻译成"实现语言"（如把"无缝循环"翻译成"gap≥视口宽"就是投机式偏离）。把静态截图当成**某一时刻的快照**，不要脑补成先后过程。
