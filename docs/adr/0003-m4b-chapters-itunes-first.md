# m4b 章节：iTunes 章节表优先、chpl 兜底

m4b 有声书存在两种互不兼容的章节标记形态：Nero 的 chpl 原子（moov/udta 内的「时间点 + 名称」列表，解析成本低）与 iTunes 章节表（moov 内独立章节轨，经 tref/chap 引用定位，章节名存样本/ilst，解析成本高）。我们决定**两种都实现，且优先解析 iTunes 章节表**（Audible 等主流有声书 m4b 采用此形态，用户已拍板 Q2）；chpl 作为兜底。只支持其一会在真实样本上出现章节缺失。章节标记两者都无时，整本 m4b 退化为普通音频文件（与 CUE 解析失败退化语义一致，Q3=A）。
